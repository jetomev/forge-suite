### D-9 · The theme's pictures are a place in Browse; Apply Background is the page's own button (Claude, from D-8)
D-8 built as Javier drew it: **Source** = the folder in use + **Browse (b)**; **Images** = every picture in it, Enter picks one and it shows below; **Fit Style** in plain names (Fill the Screen · Whole Picture · Stretched · Real Size · Repeated, each explained under the drop-down); **Apply Background (F10)**. The two points D-8 left open:

- **Apply Background (F10) belongs to the Wallpaper page**: lit when a picture or fit is picked, off otherwise. The changes bar at the bottom is the Theme Picker's (it names the theme, "and the wallpaper" when both wait). F10 anywhere applies everything picked, as before. One visible Apply per page keeps D-3 and hypeForge D-85 ("no need to have same buttons in several places").

Also: the Images list marks the picture on screen (✓) and the one picked (●); a Source that isn't there yet offers **Make Folder (n)**; Browse walks with Enter and Backspace, jumps to Home · Pictures · the KognogOS wallpapers, takes a typed path, and **Use This Folder (u)** picks the one you are in. ## 2026-10-11

### D-8 · The Wallpaper page, redesigned: a browsable folder, every picture in it, Apply Background (Javier, 2026-10-11 night) — built 2026-10-13, D-9 settles the open points
After the first Wallpaper page (D-6): *"themeForge backgrounds will need more work … 1. Source folders for background picker should be browsable 2. Available backgrounds in said folder should be all visible."* His layout, "the fixed, new version":

### D-7 · The preview at full quality, drawn over the terminal (Javier, 2026-10-11)
*"I've seen apps like superfile show image previews with great quality"*; then *"there are other apps that does it, like w3 or so … this is only possible using a x11 or wayland"*. Asked first: Alacritty speaks neither the kitty graphics protocol nor Sixel (it answered neither; Konsole answered both), so superfile in Alacritty falls back to blocks too. The w3m way works anywhere: put the picture over the terminal. Offered our own overlay or Überzug++; Javier: **our own**. `themeforge/overlay.py`, a small GTK program on gtk-layer-shell (like hypeForge's panels), not a window: Sway's placement and tuck helpers never touch it, it never takes the keyboard, clicks pass through. Before the app starts, themeForge asks the terminal its text area in pixels and its grid (`CSI 14 t`, `CSI 18 t`) → the cell size; Alacritty's padding from its settings. The overlay finds themeForge's window through Sway by the process numbers above themeForge, follows it, and hides when it isn't the window in use, isn't on screen, or themeForge says so (another page, a list open, the manual). It ends with themeForge (its input closes). The half-block preview stays underneath, shaped like the screen so both cover the same spot, and is all there is on a text console or outside Sway. Bench: `scripts/overlay-bench.py`, a real Alacritty on a hidden Sway on the graphics card, keys from hypeForge's fake keyboard: 13/13 (on the blocks within half a cell, hides and comes back, one overlay, gone at quit); with the overlay off it fails, and with list-hiding removed it fails.

### D-6 · The Wallpaper page: desktop background 1.0 (Javier, 2026-10-11)
*"Rice uses our KognogOS backgrounds only, the other themes, assign one background topic to each, and uses the color variants when they change, by default."* And for 1.0: *"All screens get the same background · Picker allows to switch a background with the user choice (from a specific folder) · Can we show in terminal a small preview of the images? … Images: centered, stretched, crop, others?"* Javier picked **Tier Aware** for the Rice. The page, the same two-column matrix: **Source** (the theme's own · KognogOS · Tier Aware · KognogOS · Arch Distro · My pictures · Solid colour) and **Fit** (Fill · Fit · Stretch · Center · Tile, Sway's own five), **Folder** (`~/Pictures/Wallpapers` by default; **Make Folder (n)** when it's missing, never made unasked) and **Picture**. Under them a **preview in half blocks** (two pixels a character), laid on a screen-shaped canvas the way Sway lays it; no extra program. The theme's own follows the Theme Picker's picks, so a combination is previewed before it's applied. The choice is written in the look file's `[wallpaper]` (picture, fit, folder) and applied by `hypeforge-theme look` (hypeForge D-93). A picture of yours stays through theme and colour changes.

### D-5 · The page: a matrix of two columns going down, compact, small buttons (Javier)
*"Page should be a matrix of 2xnumber of options going down, all drop down options to choose from. Watch spacing (real state) to make it compact with enough air between things to don't choke. Button sizes, please, not the big ones, they look awful."* The options sit two to a row (**Theme · Colors** for now), each a label and a drop-down, with the theme's line and the colour strip under them; **What this theme brings** lists the theme's elements in the same two-column way (read only until their pages come); buttons are one line, no frame.

### D-4 · themeForge writes the look file; hypeForge applies it (Javier; hypeForge D-90)
*"I believe the way to go should be to have already a config file for theme, and with the config file themeForge call to change it based on the selections on the config files for the different elements … First version theme and colors."* Apply writes the picks into `~/.config/hypeforge/look.toml` (each element's pick is kept) and runs `hypeforge-theme look`. Every run is logged (`~/.local/state/themeforge/themeforge.log`). Replaces D-2's direct `apply`.

### D-3 · One Apply button, in the bar at the bottom (Claude, from Javier's rule)
The first screenshot had **Apply (F10)** on the page and again in the changes bar. Javier, hypeForge D-85: *"no need to have same buttons in several places."* Apply stays in the bar, which shows only once something new is picked; F10 works any time. The page keeps **Undo Last Apply (u)**.

### D-2 · hypeForge does the switching (Claude)
themeForge reads hypeForge's files and runs `hypeforge-theme apply <style> <theme>` / `undo`: every look file, the backup and the reloads stay in one place (hypeForge D-59: apps read each other's files, never each other's code). Each style now carries a one-line `summary` in its `style.toml`, shown under the Theme drop-down.
