## NVIDIA

The [Hyprland wiki](https://wiki.hypr.land/Nvidia/) describes three possible driver setups and recommends the first two, *"for maximum performance and support with newer cards"*. The test desktop runs setup 2, the proprietary driver with open kernel modules. The same page warns that *"some issues could arise when using Nvidia GPUs on Hyprland that we have no control over."*

## 3D in the test VMs — solved the same night

- **Symptom:** creating the Omarchy VM with 3D on (virtio-gpu with 3D, SPICE with OpenGL) failed at start-up: `qemu-system-x86_64: egl: eglInitialize failed: EGL_NOT_INITIALIZED` / `egl: render node init failed`.
- **Isolated:** the same QEMU started fine as the normal user (`-device virtio-vga-gl -display egl-headless,rendernode=/dev/dri/renderD128`, which ran until a 4-second timer stopped it). So the card and driver were fine, and the difference was libvirt.
- **Cause:** `/etc/libvirt/qemu.conf` was all defaults. libvirt starts each VM's QEMU in a private `/dev` (`namespaces = [ "mount" ]`) holding only the devices on `cgroup_device_acl`. NVIDIA's EGL needs `/dev/nvidiactl`, `/dev/nvidia0` and `/dev/nvidia-modeset`, and none of them were on it. (They exist on the host with mode `0666`.)
- **Fix:** `scripts/test-rig/enable-nvidia-vm-3d.sh`: libvirt 12.7's seven default entries plus those three, a backup at `/var/backups/kognog/qemu.conf.20260928-220438`, then a libvirtd restart. The namespace stays on; nothing else was loosened.
- **Result, step 1:** `omarchy-ref` starts with `virtio-vga-gl` + `accel3d='yes'` and SPICE `gl enable='yes'`, boots the Omarchy 4.0.4 installer, and takes a DHCP lease as `archiso`. **But Virtual Machine Manager's window is black.** Javier reported it; the research helper had predicted it for SPICE OpenGL on NVIDIA.
- **Result, step 2:** SPICE with OpenGL off, plus an `egl-headless` display on the same render node. The card still does the 3D work, and QEMU copies finished frames into the ordinary SPICE display. **Javier sees the Omarchy installer.** A side issue on the way: virt-install had ejected the ISO after the first start, so the VM tried its empty disk. The ISO went back in, with the boot order set to CD first, then disk.
- **Worth carrying to KognogOS:** any KognogOS computer with an NVIDIA card that runs VMs with 3D will hit this. It belongs with the two `ufw` rules for `virbr0`.

## Omarchy, the reference

- `basecamp/omarchy`: MIT licence, about 43,500 stars, latest release v4.0.4 (15 September 2026), homepage omarchy.org. *(`gh api`, `gh release list`)*
- **v4.0.0 "Quattro" (14 August 2026):** the whole desktop shell was rebuilt in [Quickshell](https://quickshell.org). The bar, launcher, menus, notifications, on-screen displays, control panels, lock screen and polkit agent now run in one process. *"Waybar, Walker, Mako, SwayOSD, hyprlock, hypridle, swaybg, and polkit-gnome are all gone."* Other changes:
  - Omarchy's internals moved "from git to system packages for safely separating user modifications"
  - all Hyprland configs were converted to Lua
  - network settings moved to NetworkManager
  - the ISO is now under 6 GB

  ([release notes](https://github.com/basecamp/omarchy/releases/tag/v4.0.0))
